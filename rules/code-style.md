# 代码风格规则（全局强制）

> 适用于所有新建/修改的代码；重构既有代码时不因本规则做无关重写。

## 函数规模

1. **函数不应超过 50 行**（不含空行与注释）。超限必须拆分：按职责抽私有方法/组合式函数，或引入参数对象、策略对象。
2. **圈复杂度不应超过 10**。降低手段（按优先级）：卫语句提前返回、条件表驱动（map/switch 多态）、拆分嵌套分支为命名良好的小函数、用类型/枚举方法内聚状态判断。
3. **嵌套深度不应超过 4 层**（`if/for/while/try` 等块级嵌套累计）。超限必须展平：卫语句提前返回、`continue`/`break` 替代包裹、内层块抽为命名良好的小函数。

## 判定与例外

- 圈复杂度按常规定义：1 + 判定节点数（`if/else if/for/while/case/catch/&&/||/?:` 等各计 1）。
- 简单的机械分支（如纯映射 switch、builder 链）行数可放宽，但复杂度上限不放松——机械分支应优先改表驱动。
- 测试方法同样适用；超长测试通常是该拆参数化用例的信号。
- 评审与自检时以"能否一眼看完、能否一句话说清这个函数做什么"为最终标尺。

## 命名与表达

- 命名表达意图而非实现：类名用名词（角色/概念）、方法名用动词（用例/行为）、布尔用 `is/can/has` 前缀；与业务术语（统一语言）对齐，不造缩写黑话。
- 魔数/魔法字符串收敛为有名字的常量或枚举，状态流转规则内聚到类型上而非散落各处的 if。

## 函数与方法（设计层面）

- 一个方法做一件事；参数超过 3 个考虑参数对象；不用布尔参数切换两种行为（拆两个方法）。
- 卫语句提前返回；`else` 多半可以被提前 return 消掉。
- 副作用显性化：查询不改状态，命令有返回时说明改了什么；隐藏的全局变更（静态变量、线程上下文）是最后的手段。

## 依赖与耦合

- 依赖抽象而非实现，构造器注入；一个类的依赖超过 5 个通常是职责过宽的信号。
- 说得少的对象是好对象：不为了"将来可能用"暴露 public；包内可见性优先于 public。

## 边界与不变式

- 入边界校验（接口层），内部代码可以信任已有校验，不层层重复判空。
- 让非法状态无法表示：能用类型/构造约束表达的规则，不靠运行时 if 兜底；优先不可变对象（record/值对象），可变状态收敛到最小范围。
- 集合不返回 null（返回空集合）；单值缺失按项目惯例用 Optional 或 null，不混用。

## 错误处理

- fail fast：非法输入在最早的边界抛出，消息说明"什么非法、期望什么"。
- 不吞异常（空 catch、catch 后只打日志继续跑都是 bug 放大器）；捕获是为了恢复或转译，两者都不做就不捕获。

## 克制

- YAGNI：不实现当前用例不需要的"扩展点"；三次重复再抽象，两次重复先忍着——错误抽象比重复更难拆。
- 不留死代码、注释掉的代码、TODO 无主的坑；注释写"为什么"，"做什么"交给代码本身。
