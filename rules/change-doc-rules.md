# 变更文档设计规则（全局强制）

> 适用于所有变更（含 OpenSpec change 与不走流程的改动），在进入实施前按影响面补齐对应设计文档。

## 规则

1. **有 API 变化**（新增/修改/删除接口、出入参契约变化）→ 必须提供 API 设计文档：
   - 使用 **OpenAPI 3.x（YAML）** 编写
   - 只包含本次变化的端点，不全量复制既有接口
   - 存放位置：OpenSpec 变更放变更目录 `api/openapi.yaml`；无流程的小改动放 `docs/api/`
   - 在 design/任务拆解中引用该文档，实施以契约为准
2. **有数据库变化**（建表/改表/索引/数据迁移）→ 必须提供数据库设计文档：
   - 内容涵盖：表结构 DDL、字段说明、索引设计、迁移与回滚方案
   - 存放位置：OpenSpec 变更放变更目录 `db/design.md`；小改动放 `docs/db/`
3. 两者都没有的变更不需要补文档；**不得为凑规则虚构内容**。
